# Aegis Research OS 使用指南

本文是操作说明书：安装、五种运行模式、Web 台、报告怎么读、成本控制、扩展点。
系统定位与架构见 [README](../README.md)；工程决策的完整历史见 [HANDOFF.md](../HANDOFF.md)。

## 1. 安装与环境

```bash
# Python 3.11+（开发与 CI 在 3.12 上验证）
pip install -e ".[dev]"
pytest -q        # 1977 passed / 7 skipped，全部离线，不碰网络
```

`pyproject.toml` 是唯一依赖真源。三个**运行时可选**依赖刻意未声明（懒导入，
缺失时对应功能降级而非崩溃）：

| 包 | 缺失时的影响 |
|---|---|
| `akshare` | A 股数据主通道不可用（美股路径不受影响） |
| `openbb` | 同业对比数据增强关闭 |
| `PyMuPDF` (fitz) | 年报 PDF 抽取退回 pypdf 兜底 |

跑 A 股全量 run 前先 `pip install akshare`。

### 密钥注入

所有密钥从环境变量注入，**绝不写进仓库文件**。两种方式：

```bash
export DEEPSEEK_API_KEY="sk-..."       # 方式一：shell 环境
# 方式二：项目根建 run_research.local.sh（已 gitignore），入口脚本自动 source
```

| 变量 | 用途 | 必需性 |
|---|---|---|
| `DEEPSEEK_API_KEY` | 默认 LLM 后端 | 全量 LLM run 必需 |
| `SEC_USER_AGENT` | SEC EDGAR 要求的 UA | 入口脚本已设默认值 |
| `FMP_API_KEY` / `FRED_API_KEY` | 一致预期 / 宏观数据增强 | 可选，缺失降级 |
| `GROK_API_KEY` / `XAI_API_KEY` | 备选 LLM 后端（Grok） | 可选 |

## 2. 五种运行模式

### 2.1 全量 LLM run（正式出报告用）

```bash
./run_research.sh NVDA        # 美股：EDGAR probe 自动选最新 10-K，yfinance 实时价
./run_research.sh 300502      # A 股：akshare 主数据源，全中文研报
```

实测量级：单票约 20–30 分钟、约 20+ 次 LLM 调用、约 $0.2–0.3（DeepSeek 后端；
300502 实测 29min / 23 调用 / $0.22）。产物：`demos/<ticker>_<期>_auto_report.html`
+ thesis 持久化 + 预测记录。每次 run 结束打印 LLM 成本汇总。

常用开关（都在 `run_research.sh` 头部注释里有完整说明）：

```bash
./run_research.sh NVDA 110              # 钉住价格（回测口径）
./run_research.sh --strict-llm NVDA     # agent 兜底 mock 时直接失败（防退化报告）
FAST_AGENTS=1 ./run_research.sh NVDA    # 4/7 specialist 降 flash 档提速——
                                        # flash 档输出质量未在真实票上验证过，
                                        # 迭代用可以，正式报告别开
AEGIS_LLM_CACHE=0 ./run_research.sh NVDA  # 关磁盘缓存，强制全新 LLM 调用
```

### 2.2 规则模式（零 LLM，验数据链路）

```bash
./run_research.sh NVDA "" --no-llm    # 数据+估值+规则 agent，不调 LLM
./run_research.sh --smoke NVDA        # 冒烟：<5 分钟管道体检
```

`demos/smoke/` 里的五份样例报告就是冒烟模式产物。

### 2.3 增量模式（UPDATE=1）

```bash
UPDATE=1 ./run_research.sh 002669
```

数据、估值、报告照常刷新；**基本面摘要未变时复用上次智能体分析**——零 LLM
调用，全程小于 3 分钟。适合公告季高频回看同一批票。

### 2.4 缓存重放（改下游逻辑时的秒级迭代）

```bash
python scripts/replay_from_cache.py 300502 --allow-stale           # ~1s 重渲染报告
python scripts/replay_from_cache.py 300502 --allow-stale --editor  # 顺带重跑 Report Editor
```

从 orchestrator 落盘的 pickle 出发，跳过全部昂贵步骤（数据获取 + LLM agent），
只重跑下游（gate / decision / 渲染）。改报告模板、清洗规则、门槛逻辑时用它。

### 2.5 监控扫描（事件循环，手动触发）

```bash
python scripts/scan_watchlist.py            # 真实一轮：触发条件命中会调 LLM 复研，产生费用
python scripts/scan_watchlist.py --dry-run  # 只判触发，零副作用
python scripts/scan_watchlist.py --smoke    # rule-based 复研，零 LLM 成本
```

票池与预算在 `configs/watchlist.yaml`（含 `daily_llm_budget_usd` 当日熔断上限，
超支即停 LLM 增量简报、只留纯规则监控）。定时任务已停用（预算事故教训，见
README"诚实局限"）；如需恢复：`bash scripts/install_launchd.sh`。

## 3. 本地 Web 台

```bash
./run_server.sh    # http://127.0.0.1:8000
```

页面：`/search`（票池搜索+发起研究）、`/progress`（SSE 实时进度流）、
`/report/{slug}`（报告浏览）、`/api/*`（REST）。

⚠ 注意：`/search` 页有一个去抖 30 分钟的兜底后台扫描——手动开着 server 且
命中触发条件时会产生 LLM 费用，开 server 时心里有数。

## 4. 报告怎么读

一份报告从上往下：时效性 banner（如有）→ 执行摘要与关键数字卡 → 论点
（核心论点 / 市场定价故事 / 变体观点 / 反论点）→ DCF 三情景与敏感性矩阵 →
7 位 agent 观点与分歧 → critic 告警 → 发布门槛结果与置信度。

**置信度档位**（`aegis/core/decision_engine/engine.py`）：high / medium / low /
very_low，评分制而非一票否决，另有三道封顶：发布被 block → 封顶 low；存在
degraded 输入（LLM 兜底）→ 封顶 medium；发布门未全跑 → 封顶 medium。
**看到 medium 先查封顶原因，再看分数。**

**发布门槛**：10 道门全过才是 published（清单见
`aegis/core/publish_gate/gate.py` 模块 docstring）。报告里列出每道门的
pass/fail 与原因。

**红旗两档**：强信号词（造假 / 虚增 / 急剧恶化…）单发举旗；弱信号词（风险 /
压力 / 下滑…）需两条以上不同观察互相印证才举旗——risk_analyst 正常履职
不再制造假红旗。

**degraded 输入**：LLM 调用失败退兜底产生的警告单独计数（"N 条真实警告 +
M 条输入退化警告"），不与真实分析告警混算。看到退化计数说明该 run 的部分
agent 没吃到真 LLM，结论按 medium 以下对待。

**时效性 banner**：数据源落后最新财报期超 15 个月时强制显示——见到它，
这份报告只能当模板看，不能当分析用。

## 5. 成本控制清单

| 机制 | 位置 | 效果 |
|---|---|---|
| LLM 磁盘缓存 | `aegis/core/llm/cached_client.py`，默认开 | 相同输入的重跑免费，改一处只重付变化的调用 |
| 增量模式 | `UPDATE=1` | 基本面未变零 LLM 调用 |
| 缓存重放 | `scripts/replay_from_cache.py` | 下游迭代 ~1s，零 LLM |
| 冒烟/规则模式 | `--smoke` / `--no-llm` | 零 LLM 验管道 |
| 当日熔断 | `aegis/core/monitor/budget.py` | 扫描环当日累计成本超上限即停，跨进程台账 |
| 成本汇总 | 每次 run 结尾打印 | 单 run 花了多少一目了然 |

## 6. 扩展点

### 新增一位 specialist agent

继承 `LLMAgentBase`，只需设三个类属性（`AGENT_NAME` / `AGENT_VERSION` /
`SYSTEM_PROMPT`），参照 `aegis/core/agents/llm_agents.py` 现有 7 位的写法
（MISSION + DOMAIN EXPERTISE + PROHIBITIONS 三段式）。**铁律**：A 股路径的
`language="zh-CN"` 指令必须透传（见 `llm_agent_base.py` 的 macro_context
注入段），否则新 agent 会吐英文污染中文报告。

### 新增一个数据连接器

参照 `aegis/core/acquisition/connectors/` 任一 L1 连接器（如
`holder_count.py`）。三条红线：

1. **永不 raise**——任何失败降级为"缺失"，不崩管线；
2. **盖章只在 orchestrator**——连接器不触共享事实字典，数据来源标注在
   `auto_research.py` 编排层统一完成；
3. 新引入的百分比数字要进清洗白名单（synthesizer + report_editor 两处），
   否则会被数字清洗器当 LLM 编造数字杀掉。

连接器 docstring 里记录数据陷阱（百分数还是小数、表序、单位）是本仓库惯例，
每个陷阱配回归测试。

### 新增行业包（sector pack）

`configs/sector_packs/` 加一个 yaml（收入驱动分解式 + 行业特有关注点），
run 时 `--sector sp_xxx_v1` 指定，或按行业分类自动匹配（A 股取 akshare
行业字段，缺失时按公司名推断兜底）。

### 新增注册指标

`aegis/core/truth/registry/seed_metrics.py` 加条目。definition_gate 是硬
block：agent 引用了未注册指标会被拦，先用 `python scripts/defgate_census.py`
在缓存 run 上普查对齐率达 100% 再放行（先例：pe_ratio_ttm，HANDOFF
2026-08-13 条目）。

## 7. 常见问题

- **没有任何 API key 能跑什么？** `pytest -q` 全绿、`--smoke` / `--no-llm`
  模式、replay 重渲染（不带 `--editor`）。全量 LLM run 会在 backend 健康检查
  失败后逐 agent 退兜底——报告会生成但充满 degraded 告警，置信度封顶。
- **怎么保证两次 run 可对比？** 每次 run 的 RunManifest 冻结了 prompt 版本 /
  解析器版本 / 公式注册表版本 / sector pack 版本，报告间对比先对 manifest。
- **golden 测试为什么 skip？** `tests/golden/` 快照测试在无源 pickle 的环境
  条件跳过（7 个 skip 的来源），有源环境用 `scripts/golden_master.py` 重录。
- **改了报告渲染，怎么快速验证没改坏别的？** 先 `pytest tests/unit -q`，
  再 replay 一票看产物，大改前用 golden master 上挽具。
